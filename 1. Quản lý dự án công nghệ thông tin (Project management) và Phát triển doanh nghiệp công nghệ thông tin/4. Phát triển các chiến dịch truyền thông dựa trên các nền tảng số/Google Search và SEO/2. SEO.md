# Tối ưu cấu trúc website

### Các loại file mà Google có thể lập index

Tham khảo [tại đây](https://developers.google.com/search/docs/crawling-indexing/indexable-file-types).

### Cấu trúc URL

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/crawling-indexing/url-structure

- **Chỉ được dùng các ký tự Unicode**:
	- VD: ❌ `https://example.com/نعناع`.
	- => Dùng *percent encoding / URL coding*. VD: `https://example.com/%D9%86%D8%B9%D9%86%D8%A7%D8%B9/%D8%A8%D9%82%D8%A7%D9%84%D8%A9`.
	
- **Sử dụng ký tự `-` để phân chia các từ**:
	- VD: ❌ `https://example.com/summer_clothing/filter?color_profile=dark_grey`.
	- => `https://example.com/summer-clothing/filter?color-profile=dark-grey`.
	
- Tránh thiết kế URL quá dài, quá phức tạp, quá nhiều tham số. Googlebot sẽ tốn nhiều băng thông hơn để cào những URL như vậy.
- Lưu ý đối với các website đa ngôn ngữ: Xem [tại đây](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites#locale-specific-urls).

### Các liên kết trong website

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/crawling-indexing/links-crawlable

Googlebot sử dụng các liên kết được sử dụng trong website để khai phá các URL tiếp theo.

- Google khuyến khích sử dụng link được khai báo trong thẻ `a` với thuộc tính `href`.
- Google khuyến khích sử anchor text, hoặc thuộc tính `title` (của thẻ `a`), hoặc thuộc tính `alt` (của thẻ `img`, nếu `a` chứa `img`). Anchor text nên ngắn gọn nhưng đầy đủ, súc tích.
- Google không khuyến khích khai báo quá nhiều link liên tiếp nhau mà không có nội dung phân cách ở giữa.
- Các dạng khác vẫn có thể miễn cưỡng chấp nhận.

### Sitemap

**Tài liệu tham khảo**:
- https://www.sitemaps.org/protocol.html

**Sitemap** là file ghi lại thông tin cấu trúc website, bao gồm các URL, thông tin của chúng và quan hệ giữa các URL đó. Googlebot sử dụng sitemap để thuận tiện cào dữ liệu.

File sitemap có thể được viết bằng nhiều định dạng khác nhau, nhưng thường dùng `.xml`. 

**VD**:
`sitemap.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://www.example.com/foo.html</loc>
    <lastmod>2022-06-04</lastmod>
  </url>
</urlset>
```

File này cứ để ở nơi có thể truy cập thẳng từ root URL là được. VD: `example.com/sitemap.xml`.

### `robot.txt`

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/crawling-indexing/robots/intro

`robots.txt` là file dùng để hướng dẫn các bot của công cụ tìm kiếm (Googlebot, Bingbot...) những URL nào được phép hoặc không được phép thu thập (crawl).

>[!important]
>- ✅ `robot.txt` có thể ngăn Googlebot vào đọc một trang.
>- ❌ Không đảm bảo trang đó sẽ không xuất hiện trên Google Search.

Để ngăn 1 trang hoàn toàn không thể xuất hiện trên Google Search, sử dụng `noindex`.

**VD**:
`robots.txt`
```txt
User-agent: *
Disallow: /admin/
Disallow: /private/
```
Ý nghĩa:
- Tất cả bot (`*`).
- Không được crawl: `/admin/`, `/private/`.

File này cứ để ở nơi có thể truy cập thẳng từ root URL là được. VD: `example.com/robots.txt`.

### Chuẩn hóa URL (URL canonicalization)

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/crawling-indexing/canonicalization

Chuẩn hóa URL là quá trình **xác định một URL chính thức (canonical URL)** đại diện cho một nhóm các URL có cùng hoặc gần như cùng một nội dung.

**VD**: Giả sử một trang có thể truy cập bằng nhiều URL:
```
https://example.com/product/iphone-16
https://www.example.com/product/iphone-16
http://example.com/product/iphone-16
https://example.com/product/iphone-16?ref=facebook
https://example.com/product/iphone-16?utm_source=email
```
-> Google sẽ chọn `https://example.com/product/iphone-16` làm trang chính thay vì cào toàn bộ để tránh trùng lặp và tối ưu hiệu năng. Và cũng cho người dùng nhìn thấy thông tin thật sự thay vì các bộ lọc tìm kiếm.

Bạn muốn mọi người truy cập trang sản phẩm bán váy màu xanh thông qua `https://www.example.com/dresses/green/green-dress.html` hay `https://example.com/dresses/cocktail?gclid=ABCD`?

Googlebot có thể tự suy luận canonical URL, nhưng bạn có thể tự chỉ định nó thông qua một số cách như sau:

**Sử dụng `rel="canonical"` của thẻ `link`**:
```html
<html>
<head>
<title>Explore the world of dresses</title>
<link rel="canonical" href="https://example.com/dresses/green-dresses" />
<!-- other elements -->
</head>
<!-- rest of the HTML -->
```

**Sử dụng `rel="alternate"` của thẻ `link`**: Dùng song song với `"canonical"`, dùng để chỉ định canonical URL trong một số tình huống cụ thể, chẳng hạn như khi người dùng sử dụng điện thoại sẽ có canonical khác so với máy tính.
```html
<html>
<head>
<title>Explore the world of dresses</title>
<link rel="alternate" media="only screen and (max-width: 640px)"  href="https://m.example.com/dresses/green-dresses">
<link rel="canonical" href="https://example.com/dresses/green-dresses" />
<!-- other elements -->
</head>
<!-- rest of the HTML -->
```

**Sử dụng `rel="canonical"` của HTTP header**:
```
HTTP/1.1 200 OK
Content-Length: 19
...
Link: <https://www.example.com/downloads/white-paper.pdf>; rel="canonical"
...
```

# Tối ưu nội dung website

### Metadata

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/crawling-indexing/valid-page-metadata
- https://developers.google.com/search/docs/crawling-indexing/special-tags
- https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag

Google khuyến khích chỉ nên sử dụng các tag sau trong thẻ `head` để khai báo metadata về website:
- **`title`**: Tiêu đề trang web.
	
- **`meta`**: Các thông tin khác về trang web. Thẻ này có 2 thuộc tính là `name` (loại thông tin), và `content` (nội dung của thông tin). Gồm có các loại `name` sau:
	- `description`: Mô tả trang web (snippet).
	- `robots`: Chứa những điều các chương trình cào nội dung được làm hoặc không được làm. Ví dụ:
		- `noindex`: Không được indexing website này.
		- `nofollow`: Không được cào nội dung các website được trích dẫn trong website này.
		- `none`: `noindex` + `nofollow`.
		- `nosnippet`: Không được hiển thị snippet của website này.
		- `notranslate`: Không được dịch website này.
		- `nopagereadaloud`: Không được đọc thành tiếng website này (chức năng đọc website của trình duyệt web).
	- `property`: Thường dùng để khai báo Open Graph. Xem [[Facebook for business#Facebook Open Graph (OG) Meta Tags|tại đây]].
	- `keywords`: Chứa danh sách các từ khóa về trang web này.
	- Xem thêm danh sách các thẻ `meta` thông dụng [tại đây](https://gist.github.com/whitingx/3840905).
	
- **`link`**: Liên kết tài liệu hiện tại với một tài nguyên bên ngoài. Gồm có 1 số thuộc tính là:
	- `href`: Liên kết dẫn đến tài nguyên.
	- `rel`: Quan hệ giữa website và tài nguyên đó. Có các loại quan hệ là:
		- `stylesheet`: CSS.
		- `icon`: Favicon.
		- `help`: Trang trợ giúp.
		- ...
	- `sizes`: Kích thước ảnh (nếu tài nguyên là ảnh).
- **`script`**, **`style`**, **`base`**, **`noscript`**, **`template`**.

### Favicon

Một website hiện đại thường có rất nhiều favicon để dùng cho các thiết bị khác nhau nhằm tối ưu hiệu năng và trải nghiệm người dùng. **VD**:
```html
<!-- Favicon cho trình duyệt -->
<link rel="icon" type="image/x-icon" href="/favicon.ico">

<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png">

<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">

<link rel="icon" type="image/png" sizes="48x48" href="/favicon-48x48.png">

<!-- SVG (ưu tiên trên trình duyệt hiện đại) -->
<link rel="icon" type="image/svg+xml" href="/favicon.svg">

<!-- Apple -->
<link
  rel="apple-touch-icon"
  sizes="180x180"
  href="/apple-touch-icon.png">

<!-- Android/PWA -->
<link rel="manifest" href="/site.webmanifest">

<!-- Safari pinned tab -->
<link
  rel="mask-icon"
  href="/safari-pinned-tab.svg"
  color="#5bbad5">

<!-- Windows -->
<meta name="msapplication-TileColor" content="#2d89ef">

<!-- Theme color -->
<meta name="theme-color" content="#ffffff">
```

>[!tip]
>Sử dụng công cụ [Real Favicon Generator](https://realfavicongenerator.net/) để custom favicon từ 1 ảnh duy nhất.

### Hình ảnh

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/appearance/google-images

**Thẻ `img` gồm các thuộc tính quan trọng sau**:
- `src`: Địa chỉ hình ảnh.
- `alt`: Chú thích nội dung hình ảnh.
- `srcset`: Khai báo nhiều phiên bản kích thước khác nhau của hình ảnh (responsive).
- `sizes`: Khai báo chiều dài ảnh ở từng màn hình khác nhau (responsive).

**VD**:
```html
<img
  srcset="maine-coon-nap-320w.jpg 320w, maine-coon-nap-480w.jpg 480w, maine-coon-nap-800w.jpg 800w"
  sizes="(max-width: 320px) 280px, (max-width: 480px) 440px, 800px"
  src="maine-coon-nap-800w.jpg"
  alt="A watercolor illustration of a maine coon napping leisurely in front of a fireplace">
```

**Thẻ `picture`**: Khai báo nhiều hình ảnh khác nhau ở từng màn hình khác nhau:

**VD**:
```html
<picture>
    <source
        media="(max-width: 768px)"
        srcset="mobile.jpg">

    <source
        media="(max-width: 1200px)"
        srcset="tablet.jpg">

    <img
        src="desktop.jpg"
        alt="">
</picture>
```

### Dữ liệu có cấu trúc (Strutured data)

**Tài liệu tham khảo**:
- https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data

**Structured data** là một đoạn mã (thường ở dạng **JSON-LD** (`application/ld+json`)) được gắn vào trang web để giúp các công cụ tìm kiếm hiểu rõ nội dung trang web nói về điều gì một cách chính xác và chi tiết.

Một trang web hoàn toàn có thể chứa nhiều structured data. Mỗi structured data được đóng gói trong thẻ `script` nằm tại `head`.

>[!tip]
>- Sử dụng [Merkle Schema Markup Generator](https://technicalseo.com/tools/schema-markup-generator/) để tạo structured data.
>- Xem danh sách các loại structured data [tại đây](https://developers.google.com/search/docs/appearance/structured-data/search-gallery).
>- Sử dụng [Rich result test](https://search.google.com/test/rich-results) để kiểm tra xem trang web của bạn đã có structured data chưa.

**VD**:
```html
<html>
  <head>
    <title>How To Make Banana Bread</title>
    <script type="application/ld+json">
    {
      "@context": "https://schema.org/",
      "@type": "Recipe",
      "name": "Banana Bread Recipe",
      "image": [
        "https://example.com/photos/1x1/photo.jpg",
        "https://example.com/photos/4x3/photo.jpg",
        "https://example.com/photos/16x9/photo.jpg"
      ],
      "description": "The best banana bread recipe you'll ever find! Learn how to use up all those extra bananas.",
      "aggregateRating": {
        "@type": "AggregateRating",
        "ratingValue": 4.7,
        "ratingCount": 123
      },
      "video": {
        "@type": "VideoObject",
        "name": "How To Make Banana Bread",
        "description": "This is how you make banana bread, in 5 easy steps.",
        "contentUrl": "https://www.example.com/video123.mp4"
       }
    }
    </script>
  </head>
  <body>
  </body>
</html>
```
