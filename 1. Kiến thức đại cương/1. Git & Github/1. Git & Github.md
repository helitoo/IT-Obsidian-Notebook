# Giới thiệu

**Git**: Là một hệ thống quản lý project, có thể lưu trữ các phiên bản khác nhau của mã nguồn project trên dòng thời gian và chia sẻ với mọi người.

Có 4 loại môi trường để tương tác với git:
- **Working tree (Working directory)**:
	- Chứa các file thực tế trên máy tính mà bạn đang chỉnh sửa.
- **Staging area (Index/Stage)**:
	- Vùng trung gian chứa những thay đổi đã được chọn và chuẩn bị được đưa vào commit tiếp theo.
	- Để chọn các file/folder đưa vào staging, sử dụng `git add`.
- **Local repository**:
	- Chứa các file/folder được lưu trữ cùng với lịch sử của nó. Bạn có thể khôi phục mã nguồn về quá khứ hoặc bổ sung thêm. Mỗi một phiên bản mã nguồn được gọi là commit.
	- Commit hiện tại được ký hiệu là `HEAD`.
	- Để chọn các file/folder đưa vào local, sử dụng `git commit`.
- **Remote repository** (ví dụ `origin`):
	- Bản sao của local repository trên máy chủ (GitHub, GitLab, Bitbucket...), dùng để đồng bộ giữa nhiều máy hoặc nhiều người.
	- Để đưa dữ liệu từ local lên remote, sử dụng `git push`.

# Các lệnh cơ bản với git

**0 - Kết nối tài khoản Github với git**:
```bash
git config --global user.email "email"
git config --global user.name "name"
```

**1 - Tải repository từ Github về thiết bị**:
```sh
git clone <repository-url>

cd project
```

**2 - Kiểm tra branch hiện tại và cập nhật mã nguồn của repository trên thiết bị thành mã nguồn mới nhất trên Github**:
```sh
git checkout main
git pull origin main
```

**3 - Di chuyển sang branch khác (hoặc tạo branch mới nếu chưa có)**:
```sh
git checkout -b <branch-name>
```
Quy tắc đặt tên branch thường là:
- **`main`**: Branch chính, không được sử dụng branch này trực tiếp mà phải thông qua các branch `release` hoặc `hotfix`.
- **`release/<version>`**: Bản release.
- **`staging` / `develop`**: Branch tạm, chứa mã nguồn chưa khi đưa vào `release`.
- **`feature/<name>`**: Branch chứa các thay đổi của mã nguồn về một tính năng cụ thể của sản phẩm.
- **`hotfix/<name>`**: Branch chứa các thay đổi của mã nguồn để khắc phục một sự cố trầm trọng nào đó, có tính khẩn cấp.

**4 - Đưa mã nguồn đã thay đổi vào branch hiện tại**:
```sh
git add .
git commit -m "<name>"
```

**5 - Đưa mã nguồn tại local repository lên Github**:
```sh
git push -u origin <branch-name>
```

# Một số vấn đề dễ nhầm lẫn khi làm việc với git và Github

### `clone` và fork

- **`clone`**: Sao chép toàn bộ repository từ Github về local. Repository tại local và trên Github có liên kết với nhau.
- **Github fork**: Là tính năng của Github, cho phép tạo 1 repository mới từ 1 repository khác. Hai repository này độc lập với nhau.

### `fetch`, `pull` và Pull request (PR)

- **`fetch -a -p`**: Tải dữ liệu mới từ Github về local, bao gồm trạng thái gộp nhánh / tạo nhánh mới.
- **`pull`**: Là `fetch` rồi `merge`.
- **Pull request (PR)**: Là tính năng của Github, được sử dụng sau khi đưa code lên remote, yêu cầu `merge` được PR branch sang branch khác. Một thành viên của dự án, đóng vai trò reviewer, sẽ kiểm tra và quyết định có `merge` hay không.

### `checkout` và `switch`

| Chức năng             | `checkout`                                                                       | `switch`                  |
| --------------------- | -------------------------------------------------------------------------------- | ------------------------- |
| **Chuyển branch**     | `checkout <branch-name>`                                                         | `switch <branch-name>`    |
| **Chuyển branch**     | `checkout -b <branch-name>`<br>(*nếu branch đó chưa có thì tạo luôn branch mới*) | `switch -c <branch-name>` |
| **Quay về commit cũ** | `checkout <commit-id>`                                                           | --                        |

### `restore` và `reset`

| Lệnh          | Tác động chính                            |
| ------------- | ----------------------------------------- |
| `git restore` | Khôi phục nội dung file                   |
| `git reset`   | Di chuyển HEAD hoặc thay đổi staging area |

**VD**: `restore`: Khôi phục file về trạng thái commit gần nhất.
```sh
git restore index.js
```

**VD**: `restore`:  Bỏ lưu file trong stage.
```sh
git restore --staged index.js
```

**VD**: `reset --soft`:  Hủy commit vừa commit, đưa các file về trạng thái stage như cũ.
```sh
git reset --soft HEAD~1
```

**VD**: `reset --mixed`:  Hủy commit vừa commit và đưa các file đó ra khỏi stage.
```sh
git reset HEAD~1
```

**VD**: `reset --hard`:  Hủy commit vừa commit và đưa các file đó ra khỏi working tree.
```sh
git reset --hard HEAD~1
```

# Git graph, Branch và Lane

**Branch**:
- Là 1 con trỏ trỏ tới 1 commit tại 1 thời điểm.
- 1 commit có thể thuộc nhiều branch.

**Git graph**:
- Là sơ đồ mô tả sự xuất hiện của các commit.
- Đơn vị vẽ là *lane*. **Lane** là đoạn thẳng nối giữa các commit. Trên một lane có thể có nhiều commit.

**Lệnh xem git graph**:
```sh
git log --graph --oneline --all
```

Git graph có thể được xem một cách trực quan hơn ở GUI thông qua extension **Git Graph** (mhutchie).

### Một commit được trỏ bởi một branch

Mỗi lần có thêm 1 commit mới, branch sẽ trỏ đến commit mới nhất.

![[1-commit-1-branch.svg]]

```sh
git checkout main
git commit -m "A"
git commit -m "B"
git commit -m "C"
```

### Một commit được trỏ bởi nhiều branch

Xảy ra khi các branch được tạo ra nhưng tại mỗi branch, chưa có commit mới. Tức là các branch đều trỏ tới commit lúc mới tạo ra.

![[1-commit-n-branches.svg]]

```sh
git checkout main
git commit -m "A"
git branch feature/a
git branch release/a
```

### Lane, `merge` và `rebase`

**`merge`**: Git sẽ tự thực hiện các hành vi sau:
1. Đưa các thay đổi của `feature` vào `main` -> Có thể xảy ra (*conflict*), ở cùng một đoạn code nhưng ở `feature` và `main` có những biến thể khác nhau, lập trình viên cần chọn một trong hai để giữ lại.
2. Tạo một commit mới là merge commit.
3. Trỏ `main` sang merge commit.

```sh
git checkout main
git merge feature
```

**`rebase`**: Git sẽ tự thực hiện các hành vi sau:
1. Sao chép lịch sử commit của `feature` và nối vào commit mới nhất của `main`. Tức là đã ghi đè `main` bằng `feature` -> Không có conflict.
2. Trỏ `feature` sang commit mới nhất.

```sh
git checkout feature
git rebase main
```

**Lane** có thể biểu diễn diễn biến commit, bao gồm *branching (tạo lane mới)* và *merging (gộp các lane)*.
- **Branching**: Khi một branch mới được tạo và bắt đầu có lịch sử commit riêng, Git graph sẽ tách thành một lane mới.
- **Merging**: Xảy ra khi có sự hợp nhất giữa 1 branch của lane chính và branch của lane phụ (thông qua `merge`).

>[!caution]
>`rebase` không merging. Muốn merging bằng `rebase` thì phải **`merge` sau khi `rebase`**.
