
# Tổng quan

**MapReduce** là 1 mô hình lập trình và framework xử lý dữ liệu phân tán.

### Ý tưởng cốt lõi

Dev chỉ cần viết hai hàm, còn việc chia dữ liệu, lập lịch, xử lý lỗi, truyền dữ liệu giữa các máy đều do framework đảm nhiệm.

MapReduce hoạt động dựa trên 2 hàm cốt lõi sau:
- **Map**: Là hàm biến đổi dữ liệu, có tính độc lập, các mapper không cần giao tiếp nhau để hoạt động, được gửi đến tận nơi lưu trữ liệu để xử lý (*locality*).
- **Reduce**: Nhận tất cả value có cùng key, tổng hợp lại thành kết quả cuối.

Map và Reduce đều có output và input là các cặp `(k, v)` (key - value) và quy trình hoạt động của MapReduce là:
1. **Map**: $\text{map}(k,v)\rightarrow[(k',v')]$: Biến đổi từng cặp key - value, mỗi cặp do 1 hàm map biến đổi, tổng hợp toàn bộ dữ liệu là danh sách các cặp key - value.
2. 2 bước sau đây là tùy chọn:
	1. **Combine**: $\text{combine}(k',[v'])\rightarrow[(k',v'_{\text{local}})]$: Là một dạng mini-reduce, dùng để gộp trước một số cặp key - value để giảm lưu lượng truyền qua mạng.
	2. **Partition:** $\text{partition}(k',\ R)\rightarrow n$: Phân mảng các cặp key - value thành các cặp khác nhau nhằm đưa đến các reducer khác nhau.
3. **Shuffle & Sort**: $[(k',v')]\rightarrow[(k',[v'])]$ Gôm nhóm các cặp key - value lại. Sau khi gôm nhóm, mỗi key có thể có nhiều value.
4. **Reduce**: $\text{reduce}(k',[v'])\rightarrow[(k',v'')]$: Xử lý dữ liệu tổng hợp và cho ra các cặp key - value kết quả cuối cùng.

>[!question] Tại sao cần `(key, value)`
>Nguyên lý *data locality* giải quyết bài toán đọc dữ liệu bằng cách đưa bộ xử lý đến tận nơi lưu trữ dữ liệu. Nhưng dữ liệu thì nằm rải rác ở nhiều nơi, vậy làm sao cho ra kết quả xử lý tổng hợp được?
>*Key* chính là chìa khóa để giải quyết bài toán này.

|           | Ý nghĩa                                                          | Trả lời cho câu hỏi... |
| --------- | ---------------------------------------------------------------- | ---------------------- |
| **Key**   | Nhãn định danh giúp gom nhóm các dữ liệu liên quan lại với nhau. | Dữ liệu ở đâu?         |
| **Value** | Dữ liệu cần tính toán.                                           | Giá trị cụ thể là gì?  |

### Hạn chế

MapReduce không hoạt động tốt với
- Những vấn đề lặp đi lặp lại.
- Bài toán đệ quy.
- Xử lý dữ liệu luồng (stream).

**Xây dựng `map()`**: Mở rộng từ lớp `Mapper` của Hadoop.

Lớp `Mapper` xử lý đối tượng có các thành phần dữ liệu sau:
- `Object`: Kiểu dữ liệu của khóa đầu vào.
- `Text`: Kiểu dữ liệu của giá trị đầu vào.
- `Text`: Kiểu dữ liệu của giá trị đầu ra.
- `Object`: Kiểu dữ liệu của khóa đầu ra.

```java
public static class TokenizerMapper
	extends Mapper<Object, Text, Text, IntWritable>{
	// ...
```

Hàm chính `map` có 3 tham số sau:
- `Object key`: Offset (vị trí byte) của dòng hiện tại trong tập tin đầu vào. Dù không trực tiếp sử dụng trong hàm, tham số này vẫn bắt buộc phải có để tuân thủ các quy tắc của Mapper.
- `Text value`: Nội dung của một dòng văn bản trong tập tin đầu vào.
- `Context context`: Dùng để ghi đầu ra của Mapper.

Mỗi server sẽ chỉ triển khai 1 lớp `Mapper`, với mỗi đơn vị dữ liệu thì hàm `map` sẽ thực thi một lần.

Tổng kết:
```java
public static class TokenizerMapper
	extends Mapper<Object, Text, Text, IntWritable>{
		
		private final static IntWritable one = new IntWritable(1);
		
		private Text word = new Text();
		
		// Hàm chính
		public void map(Object key, Text value, Context context)
			throws IOException, InterruptedException {
			// Tách chuỗi thành các từ (token)
			// phân cách bởi khoảng trắng
			StringTokenizer itr = new StringTokenizer(value.toString());
			
			// Lặp qua từng token và +1 vào context (đại diện cho số lượng)
			while (itr.hasMoreTokens()) {
				word.set(itr.nextToken());
				context.write(word,one);
		}
	}
}
```

**Xây dựng `reduce()`**: Mở rộng từ lớp `Reducer` của Hadoop.

Lớp `Reducer` xử lý đối tượng có các thành phần dữ liệu sau:
- `Text`: Key đầu vào / đầu ra.
- `IntWritable`: Kiểu dữ liệu của các phần tử trong danh sách giá trị đầu vào / đầu ra.

Hàm chính `reduce` có 3 tham số sau:
- `Text key`: Key.
- `Iterable<IntWritable> values`: Danh sách value sau khi gôm nhóm.
- `Context context`: Context.

Hàm `reduce` chỉ được gọi một lần ứng với mỗi key.

```java
public static class IntSumReducer
	extends Reducer<Text, IntWritable, Text, IntWritable> {
	
	private IntWritable result = new IntWritable();
	
	public void reduce(Text key, Iterable<IntWritable> values, Context context )
		throws IOException, InterruptedException {
		int sum = 0;
		for (IntWritable val : values)
			sum += val.get();
		result.set(sum);
		context.write(key, result);
	}
}
```

**Xây dựng `driver()`**: Hàm này chạy ở máy chính (master)

```java
public static void main(String[] args)
	throws Exception {
		Configuration conf = new Configuration();
		String[] otherArgs = new GenericOptionsParser(conf, args).getRemainingArgs();
		if (otherArgs.length != 2) {
			System.err.println("Usage: wordcount <in> <out>");
			System.exit(2);
		}
	
	Job job = new Job(conf, "word count");
	job.setJarByClass(WordCount.class);
	job.setMapperClass(TokenizerMapper.class);
	job.setCombinerClass(IntSumReducer.class);
	job.setReducerClass(IntSumReducer.class);
	job.setOutputKeyClass(Text.class);
	job.setOutputValueClass(IntWritable.class);
	
	FileInputFormat.addInputPath(job, new Path(otherArgs[0]));
	FileOutputFormat.setOutputPath(job, new Path(otherArgs[1]));
	System.exit(job.waitForCompletion(true) ? 0 : 1);
}
```

# Một số design pattern trên MapReduce

### Local aggregation (Tổng hợp cục bộ)

Trong xử lý phân tán dữ liệu lớn, khía cạnh quan trọng nhất của **đồng bộ hóa** là **trao đổi kết quả trung gian**: sao chép kết quả từ các mapper sang các reducer. Việc này tốn kém vì:
- Trước hết phải **truyền dữ liệu qua mạng** (giai đoạn xáo trộn, shuffle).
- Trong Hadoop, các kết quả trung gian còn được **ghi xuống đĩa**, nên tốc độ đọc/ghi đĩa cũng ảnh hưởng đến hiệu năng.
- Giảm độ trễ của mạng và đĩa bằng phần cứng là rất đắt đỏ.

Vì vậy hướng tiếp cận hiệu quả hơn là: **giảm lượng dữ liệu trung gian**. Ít dữ liệu cần xáo trộn hơn thì thuật toán chạy nhanh hơn.

**Tổng hợp cục bộ (local aggregation)** là design pattern gom và cộng dồn kết quả ngay tại phía mapper trước khi gửi qua mạng --> số lượng và kích thước của các cặp khóa-giá trị đưa vào quá trình xáo trộn giảm đi.

VD: Thay vì gửi 1000 cặp `("A", 1)` từ một mapper, ta gộp lại và chỉ gửi một cặp `("A", 1000)`.

Có ba kỹ thuật để thực hiện, sắp xếp từ đơn giản đến kiểm soát nhiều nhất:

| Kỹ thuật                           | Ý tưởng                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------- |
| **Combiner**                       | Một bước "mini-reduce" chạy sau map, do Hadoop điều phối                     |
| **Combine trong mapper (cơ bản)**  | Mapper tự gom bằng mảng liên kết trong **một lần gọi** `MAP`                 |
| **In-mapper combining (nâng cao)** | Mapper giữ trạng thái **xuyên suốt nhiều lần gọi** `MAP`, và chỉ emit ở cuối |

#### Combiner

Combiner trong Hadoop hoạt động như một reducer cục bộ trên đầu ra của mapper, giúp giảm lượng dữ liệu cần xáo trộn.

**Hạn chế**:
- **Hadoop không đảm bảo combiner luôn được chạy**: Framework có thể chạy nó 0, 1 hoặc nhiều lần, nên thuật toán không được phụ thuộc vào việc combiner có chạy hay không.
- Mapper **vẫn phải emit toàn bộ cặp khóa-giá trị** thô, rồi combiner mới gộp. Nghĩa là combiner "chỉ" giảm dữ liệu cần xáo trộn, chứ không giảm chi phí tạo ra các cặp đó.
- Combiner có thể **tốn CPU và I/O** (tạo, tuần tự hóa, ghi tạm và đọc lại các cặp trung gian).

#### Tổng hợp cục bộ trong lớp mapper bằng mảng liên kết

**Ý tưởng**:
- Dùng một **mảng liên kết** (associative array, tương tự dictionary/map) để tích lũy kết quả ngay trong phương thức `MAP`.
- Phương thức `EMIT` chỉ được gọi **sau khi xử lý xong toàn bộ nội dung của một bản ghi đầu vào** (ở đây là một tài liệu).

**VD**: Đếm từ (phiên bản cải tiến 1):
```
class MAPPER
  method MAP(docid a, doc d)
    H ← new ASSOCIATIVEARRAY
    for all term t ∈ doc d do
      H{t} ← H{t} + 1
    for all term t ∈ H do
      EMIT(term t, count H{t})
```

**Nhược điểm**: Phạm vi tổng hợp mới chỉ trong **một đơn vị dữ liệu** (`doc`). Dữ liệu từ các đơn vị khác nhau trên cùng một máy vẫn chưa được gộp.

#### Duy trì trạng thái trên toàn bộ map task

Trong Hadoop, một đối tượng mapper được tạo ra cho mỗi tác vụ map task (ứng với đơn vị dữ liệu đầu vào) và dùng cho nhiều lần gọi `map`. Vì thế mapper có thể duy trì trạng thái trong và trên toàn bộ các lần gọi `map`.

Hai phương thức được dùng:
- **`INITIALIZE`**: Được gọi 1 lần trước khi xử lý, dùng để tạo cấu trúc dữ liệu dùng chung cho tất cả các lần gọi `map`.
- **`CLOSE`**: Được gọi 1 lần sau khi tất cả bản ghi của map task hoàn thành, dùng để emit các cặp khóa-giá trị trung gian.

**VD**: Đếm từ (phiên bản cải tiến 2):
```
class MAPPER
  method INITIALIZE
    H ← new ASSOCIATIVEARRAY

  method MAP(docid a, doc d)
    for all term t ∈ doc d do
      H{t} ← H{t} + 1

  method CLOSE
    for all term t ∈ H do
      EMIT(term t, count H{t})
```

**Hạn chế**:
- **Giới hạn bộ nhớ**: `H` lớn dần theo số lượng khóa phân biệt, nếu có quá nhiều khóa phân biệt, có thể tràn bộ nhớ --> emit và xóa `H` định kỳ sau mỗi N bản ghi (hoặc khi đạt một ngưỡng nào đấy).
- **Trạng thái nằm trong mapper:** Thuật toán có thể nhạy cảm với thứ tự xử lý, cần thiết kế cẩn thận hơn so với một hàm `map` thuần.

### Pairs and stripes (Cặp và sọc)

Một cách tiếp cận khác trong MapReduce là **xây dựng các khóa-giá trị phức tạp** (thay vì chỉ dùng chuỗi hay số đơn giản).

Có 2 kỹ thuật cơ bản:

| Kỹ thuật             | Ý tưởng                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| **Pairs**<br>(Cặp)   | Dùng một **cấu trúc phức tạp làm khóa**.                                                        |
| **Stripes**<br>(Sọc) | Dùng một **cấu trúc dữ liệu phức tạp làm giá trị**, gom trong bộ nhớ của mapper (mảng kết hợp). |

**VD: Ma trận từ đồng hiện $M_{n\times n}$** (co-occurrence matrix) của một kho ngữ liệu bao gồm:
- $n$: Số lượng từ khác nhau trong 1 từ điển.
- $m_{ij}$: Số lần từ $w_i$ xuất hiện cùng với từ $w_j$ trong một ngữ cảnh, ví dụ như một câu, đoạn, tài liệu,... gồm $t$ từ.

#### Phương pháp Pairs

Coi mỗi cặp từ đồng hiện là **một khóa trung gian riêng**, giá trị là số đếm.
- **Mapper** xử lý một câu/đoạn/văn bản: sinh tất cả cặp từ đồng hiện, với mỗi cặp phát ra `(a, b) → 1`.
- **Reducer** cộng tần số đồng hiện của từng cặp.
- Đầu ra là cặp từ cùng tần suất, **tương ứng với một ô của ma trận**.
- Nên dùng **combiner** để giảm dữ liệu xáo trộn.

```text
class MAPPER
  method MAP(docid a, doc d)
    for all term w ∈ doc d do
      for all term u ∈ NEIGHBORS(w) do
        EMIT(pair (w, u), count 1)

class REDUCER
  method REDUCE(pair p, counts[c1, c2, ...])
    s ← 0
    for all count c ∈ counts[c1, c2, ...] do
      s ← s + c
    EMIT(pair p, count s)
```

#### Phương pháp Stripes

Nhóm các cặp có cùng từ đầu thành một mảng kết hợp (associative array). Khóa là một từ, giá trị là "sọc" chứa số đếm của các từ đồng hiện với nó.
- **Mapper** xử lý một câu/đoạn/văn bản: với mỗi từ w, phát ra `w → { u1: count, u2: count, ... }`.
- **Reducer** thực hiện **tính tổng theo từng phần tử** (element-wise) của các mảng kết hợp có cùng khóa.

VD: Các cặp:
```text
(a, b) → 1
(a, c) → 2
(a, d) → 5
(a, e) → 3
(a, f) → 2
```

trở thành một sọc duy nhất:
```text
a → { b: 1, c: 2, d: 5, e: 3, f: 2 }
```

```text
class MAPPER
  method MAP(docid a, doc d)
    for all term w ∈ doc d do
      H ← new ASSOCIATIVEARRAY
      for all term u ∈ NEIGHBORS(w) do
        H{u} ← H{u} + 1
      EMIT(term w, stripe H)

class REDUCER
  method REDUCE(term w, stripes[H1, H2, ...])
    Hf ← new ASSOCIATIVEARRAY
    for all stripe H ∈ stripes[H1, H2, ...] do
      SUM(Hf, H)
    EMIT(term w, stripe Hf)
```

**So sánh Pairs và Stripes**:

| Tiêu chí                | Pairs                                         | Stripes                                                           |
| ----------------------- | --------------------------------------------- | ----------------------------------------------------------------- |
| **Khóa trung gian**     | Cặp từ, rất nhiều và ngắn                     | Một từ, ít hơn nhưng giá trị lớn                                  |
| **Số cặp khóa-giá trị** | Rất lớn                                       | Ít hơn nhiều                                                      |
| **Dữ liệu qua mạng**    | Nhiều (đặc biệt cặp trung gian)               | Gọn hơn                                                           |
| **Chi phí sắp xếp**     | Cao                                           | Thấp hơn                                                          |
| **Giá trị**             | Đơn giản (một số nguyên)                      | Phức tạp (mảng kết hợp), tốn chi phí ghi đĩa/khôi phục trạng thái |
| **Lợi ích từ combiner** | **Hạn chế**: khóa là cặp từ ít lặp lại cục bộ | **Rất nhiều**: tập khóa chính là tập từ vựng                      |
| **Nguy cơ tràn bộ nhớ** | **Không có**                                  | **Có**, nếu thiết kế không đúng cách                              |
