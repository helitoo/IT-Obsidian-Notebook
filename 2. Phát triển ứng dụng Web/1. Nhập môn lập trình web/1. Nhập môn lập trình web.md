# Web

**Web** là các dịch vụ cung cấp thông tin đa phương tiện (*multimedia*) dựa trên *hypertext*.
- **Phân tán**: Được cài đặt trên nhiều server khắp nơi trên thế giới.
- **Hypertext (Siêu văn bản)**: Là kỹ thuật sử dụng văn bản để truy cập thông tin, có thể trỏ đến các siêu văn bản hoặc tài nguyên khác (*hyperlink*).

# Website và Web application

**Website**: Là tập hợp các tài nguyên web cùng một tên miền.

**Web application**: Là một ứng dụng chạy trên web, có logic nghiệp vụ đọc/ghi dữ liệu và xác thực.

| Tiêu chí               | Website                                                   | Web Application                                                                |
| ---------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Mục đích**           | Cung cấp thông tin                                        | Thực hiện tác vụ, xử lý nghiệp vụ                                              |
| **Tương tác**          | Một chiều (đọc là chính)                                  | Hai chiều (nhập liệu, xử lý, phản hồi)                                         |
| **Ví dụ**              | Blog, báo điện tử, landing page, trang giới thiệu công ty | Gmail, Facebook, Google Docs, phần mềm quản lý bán hàng                        |
| **Yêu cầu đăng nhập**  | Thường không cần                                          | Thường cần tài khoản                                                           |
| **Độ phức tạp**        | Đơn giản đến trung bình                                   | Trung bình đến rất phức tạp                                                    |
| **Xử lý dữ liệu**      | Ít hoặc không có database động                            | Thường có database, xử lý real-time                                            |
| **Cập nhật nội dung**  | Ít thay đổi, cập nhật theo đợt                            | Nội dung/dữ liệu thay đổi liên tục theo hành vi người dùng                     |
| **Công nghệ**          | HTML/CSS + ít JS                                          | HTML/CSS/JS + backend (*API, database, framework như React, Vue, Node.js,...*) |
| **SEO**                | Thường tối ưu SEO tốt (nội dung công khai)                | Ít quan trọng vì nội dung sau đăng nhập                                        |
| **Chi phí phát triển** | Thấp hơn                                                  | Cao hơn (do logic nghiệp vụ phức tạp)                                          |

>[!note]
>Thường thì web app và website được coi như một.

# PWA (Progressive Web Apps)

Là các ứng dụng web được xây dựng bằng các công nghệ web thông thường (*HTML, CSS, JavaScript*) nhưng được thiết kế để mang lại trải nghiệm giống như ứng dụng gốc (native app) trên điện thoại hoặc máy tính.
- **A web manifest**: Có file JSON mô tả *tên app, icon, màu sắc, cách hiển thị khi cài đặt,...*
- **A service worker**: Script chạy nền, xử lý cache, offline, push notification.
- **HTTPS**: Phải chạy trên nền giao thức này để đảm bảo bảo mật.

# Web browser

**Web Browser** (trình duyệt web) là một phần mềm cho phép người dùng **truy cập, hiển thị và tương tác** với các trang web trên Internet.

# CDN (Content Delivery Network)

**CDN (Content Delivery Network - Mạng phân phối nội dung)** là một hệ thống gồm nhiều server được đặt tại nhiều địa điểm khác nhau trên thế giới, có nhiệm vụ lưu trữ và phân phối nội dung (*hình ảnh, video, CSS, JavaScript, file tĩnh,...*) đến người dùng từ server gần họ nhất về mặt địa lý.

**Lợi ích:**
- **Tăng tốc độ tải trang**: Do giảm được khoảng cách vật lý giữa server và người dùng.
- **Giảm tải cho server gốc**: Vì phần lớn yêu cầu được xử lý bởi CDN.
- **Tăng khả năng chịu tải**: Xử lý được lượng truy cập lớn cùng lúc (traffic spike).
- **Bảo mật tốt hơn**: Nhiều CDN tích hợp chống DDoS, tường lửa (WAF).
- **Độ tin cậy cao**: Nếu 1 server CDN gặp sự cố, hệ thống tự chuyển sang server khác.

# FE (Front-end) và BE (Back-end)

**Front-end**: Phần **giao diện người dùng** nhìn thấy và tương tác trực tiếp trên trình duyệt (những gì hiển thị trên màn hình). Đối với các ứng dụng web server-side rendering, server có thể đảm nhiệm cả front-end.

**Back-end**: Phần **xử lý phía sau**, chạy trên server - nơi lưu trữ dữ liệu, xử lý logic nghiệp vụ, mà người dùng không nhìn thấy.

| Tiêu chí                        | Front-end                                          | Back-end                                                           |
| ------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------ |
| **Vai trò**                     | Hiển thị giao diện, tương tác với người dùng       | Kết nối với cơ sở dữ liệu, xử lý dữ liệu, logic nghiệp vụ, bảo mật |
| **Chạy ở đâu**                  | Trình duyệt (client-side)                          | Máy chủ (server-side)                                              |
| **Người dùng nhìn thấy**        | Có (giao diện, hình ảnh, nút bấm...)               | Không (ẩn phía sau)                                                |
| **Ngôn ngữ chính**              | HTML, CSS, JavaScript,...                          | PHP, Python, Java, Node.js, Ruby, C#,...                           |
| **Framework/Thư viện phổ biến** | React, Vue, Angular, Next.js,...                   | Express, Django, Spring Boot, Laravel, .NET,...                    |
| **Ví dụ công việc**             | Thiết kế layout, animation, responsive, xử lý form | Xác thực người dùng, xử lý thanh toán, API, bảo mật dữ liệu        |
| **Công cụ hỗ trợ**              | Chrome DevTools, Figma,...                         | Postman, Docker,...                                                |

# SPA (Single Page Application)

**Single Page Application (SPA)** là một kiểu ứng dụng web chỉ tải **một trang HTML duy nhất**, sau đó khi người dùng điều hướng (*chuyển trang, bấm menu...*), nội dung sẽ được **cập nhật động** bằng JavaScript mà **không cần tải lại toàn bộ trang** từ server.

**Đặc điểm**:
- **Chỉ load 1 lần**: Các file HTML, CSS, JS được tải về một lần duy nhất khi truy cập lần đầu.
- **Không reload trang**: Chuyển trang không bị giật, trắng màn hình.
- **Giao tiếp qua API**: Dữ liệu được lấy về dạng JSON qua AJAX/Fetch, không phải HTML render sẵn từ server.
- **Routing phía client**: Việc điều hướng URL (*`/home`, `/profile`,...*) do JavaScript xử lý (client-side routing), không phải server.

**Ưu điểm**:
- Trải nghiệm mượt, nhanh như ứng dụng native.
- Giảm tải cho server (server chỉ trả dữ liệu JSON, không phải render cả trang HTML).
- Tách biệt rõ ràng FE và BE (dễ phát triển song song).

**Nhược điểm**:
- **SEO khó hơn**: vì nội dung được render bằng JavaScript, một số công cụ tìm kiếm khó đọc được (phải dùng thêm kỹ thuật như SSR - Server Side Rendering để khắc phục).
- **Tải lần đầu chậm hơn**: vì phải tải toàn bộ file JS cần thiết ngay từ đầu.
- Nếu JavaScript lỗi, cả trang có thể bị "trắng" (không có nội dung dự phòng).

# Static web và Dynamic web

**Static Web (Web tĩnh)**: Trang web có nội dung **cố định**, giống nhau với mọi người dùng, mọi lần truy cập - trừ khi lập trình viên chỉnh sửa trực tiếp trong file.

**Dynamic Web (Web động)**: Trang web có nội dung **thay đổi linh hoạt**, tùy theo dữ liệu, thời gian, hoặc theo từng người dùng cụ thể - được xử lý và tạo ra "ngay tại thời điểm truy cập".

# Module Loaders và Module Bundlers

**Vấn đề**:
- Khi viết JavaScript cho dự án lớn, bạn không thể viết tất cả code vào 1 file - cần chia nhỏ thành nhiều **module** (file) để dễ quản lý.
- Nhưng trình duyệt (đặc biệt là các trình duyệt cũ) **không hiểu** cách các file này liên kết với nhau, hoặc tải chúng không hiệu quả (quá nhiều request). Đây là lý do ra đời Module Loaders và Bundlers.

### Module Loader

**Module Loader** là công cụ **tải và thực thi module tại thời điểm thực thi mã (runtime)**, giải quyết vấn đề: file này cần dùng biến/hàm từ file khác thì làm sao "import" được.

| Loader                                   | Cú pháp                        | Đặc điểm                                                                  |
| ---------------------------------------- | ------------------------------ | ------------------------------------------------------------------------- |
| **CommonJS (CJS)**                       | `require()` / `module.exports` | Dùng trong Node.js, load đồng bộ (synchronous)                            |
| **AMD (Asynchronous Module Definition)** | `define()`                     | Dùng cho trình duyệt, load bất đồng bộ.                                   |
| **ES Modules (ESM)**                     | `import` / `export`            | Chuẩn chính thức của JavaScript hiện đại, được trình duyệt hỗ trợ native. |

### Module Bundler

**Module bundler** là công cụ **gộp nhiều file module lại thành 1 (hoặc một vài) file duy nhất** trước khi đưa lên production, giúp:
- Giảm số lượng HTTP request (thay vì tải 50 file JS, chỉ tải 1-2 file).
- Chuyển đổi code mới (ES6+, TypeScript, JSX) thành code cũ hơn mà trình duyệt hiểu được (qua Babel).
- Tối ưu hóa: nén code (minify), loại bỏ code không dùng (tree shaking)
- Xử lý cả CSS, hình ảnh, font như một phần của quá trình build.

|Bundler|Đặc điểm|
|---|---|
|**Webpack**|Mạnh mẽ, cấu hình linh hoạt, phổ biến nhất trong nhiều năm|
|**Vite**|Cực nhanh (dùng ES Modules native khi dev), đang rất thịnh hành|
|**Parcel**|Cấu hình gần như bằng 0 (zero-config)|
|**Rollup**|Tối ưu cho việc build thư viện (library)|
|**esbuild**|Viết bằng Go, tốc độ build siêu nhanh|

# Graceful Degradation (GD) - Progressive Enhancement (PE)

**Vấn đề**:
- Không phải ai cũng dùng trình duyệt mới nhất, mạng nhanh, hay thiết bị mạnh.
- Vậy nên xây dựng như thế nào để **ai cũng dùng được**, dù trải nghiệm có thể khác nhau?

### Graceful Degradation

Xây dựng trải nghiệm **đầy đủ, hiện đại nhất trước** (cho trình duyệt mới, thiết bị mạnh) → sau đó đảm bảo nếu trình duyệt/thiết bị không hỗ trợ, trang vẫn **hoạt động được ở mức cơ bản** (không bị vỡ hoàn toàn).

**VD**:
```css
.box {
  background: red; /* fallback cho browser cũ */
  background: linear-gradient(to right, red, blue); /* hiệu ứng đẹp cho browser mới */
}
```

### Progressive Enhancement

Xây dựng **phiên bản cơ bản nhất, hoạt động ổn định trước** (HTML thuần, không cần JS/CSS phức tạp) → sau đó **thêm dần** các tính năng nâng cao (CSS đẹp, hiệu ứng JS) cho trình duyệt nào hỗ trợ.

**VD**:
```html
<!-- HTML cơ bản: form vẫn submit được dù JS tắt -->
<form action="/search" method="GET">
  <input type="text" name="q">
  <button type="submit">Tìm kiếm</button>
</form>
```
```js
// Sau đó thêm JS để "nâng cấp" trải nghiệm (search gợi ý real-time, không cần load lại trang)
if ('fetch' in window) {
  // thêm tính năng AJAX search
}
```

# State management

**State Management (Quản lý trạng thái)** là cách tổ chức, lưu trữ và cập nhật **dữ liệu thay đổi theo thời gian** trong một ứng dụng - đặc biệt quan trọng trong các ứng dụng có nhiều tương tác như SPA.

**State**: Là dữ liệu tại một thời điểm, có ảnh hưởng đến việc hiển thị giao diện.
